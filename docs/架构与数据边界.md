# 架构与数据边界

## 实际交付目标

优先完成本机可操作的数据分析闭环，将平台数据连接与分析模块解耦。用户已授权直接实施框架；未授权购买第三方数据服务或将评论发送给外部模型。

## 数据流

输入链接／关键词 → 单采集任务调度 → 独立平台浏览器 → 正常页面加载的评论响应／可见评论 → 规范化 → SQLite 任务快照 → 中文分词／需求分类 → 原文证据／导出。

文件入口：预览上传 → 自动／人工字段映射 → 规范化 → 同一数据库与分析流程。

## 数据源验证

核对日期：2026-10-04。

- 抖音官方评论接口需要应用权限及用户授权，不是任意全平台评论搜索接口：https://open.douyin.com/platform/resource/docs/openapi/interaction-management/comment-management-user/comment-list/
- 本次查到的小红书开放平台文档主要是电商数据，不能据此假设有任意笔记评论的通用官方接口：https://school.xiaohongshu.com/en/open/index.html
- 选择通过本机独立浏览器读取平台正常返回的页面内容。不复用用户常用浏览器配置，不读取其他项目的登录资料，不重放带签名的私有请求。
- 未登录真实探测保存在 `output/verification/platform-probe.json`：抖音验证码中间页、小红书无作品搜索结果。用户已完成登录；对用户新提供的小红书笔记已续采到80条真实评论，最新记录在 `output/verification/self-audit-live.json`，当前为部分读取。抖音真实采集尚未通过（曾遇验证码，最新搜索无作品返回）；受控测试只能证明软件流程。
- 若网页始终不可读取，可导入自行导出的评论；第三方数据服务应后续单独评估覆盖、价格与权限。

## 一致性与恢复

- 平台 + 作品 + 评论 ID 为首选唯一标识。缺 ID 时用内容、作者、时间、父评论、作品生成指纹。
- 去重在数据库唯一约束中完成，重复导入不增加任务评论总数。
- 每个任务保留自己的评论快照，后续任务更新点赞数不会静默改动历史任务。
- 原始导入行中的未知列不存入评论库；仅存分析所需字段。暂存导入预览 15 分钟自动失效。
- 采集数据随每次页面响应入库；服务重启后运行任务标记暂停。继续时跳过已完成／达到上限的作品；未完成作品重开并去重。
- 保存成功记录和失败来源；不把登录拦截、空搜索或解析失败标成成功获取。

## 分析口径

- 关键词：本地 `Intl.Segmenter` 中文分词、停用词、同义词和关注词；评论数、出现次数、作品数分别统计。
- 需求：求方法、遇到困难、购买咨询、对比选择、场景需求；可重叠，点击后展示匹配原文。
- 选题建议是规则生成，未接入大模型，不承诺复杂反讽或隐含需求识别。
- 日期筛选按北京时间；缺失时间的记录在指定日期范围分析中排除，但原数据保留。
- 疑似推广／无有效文本默认不纳入分析，可切换纳入。不会物理删除原记录。
- 结果没有全量覆盖率百分比，因为没有可靠的总体分母。显示的是已获取作品／评论及来源处理状态。

## 访问与输出

- localhost HTTP 服务验证 Host 和跨站写请求；API 不接受任意网页抓取地址。
- HTML 转义；CSV 对表格公式前缀做中和；Excel 文本以字符串写入。
- 采集浏览器和分析数据库仅在 `.runtime/`；源码忽略运行数据。
- 演示数据需用户主动选择，界面和导出文件标记 DEMO，不与真实任务混合。

## 实采校正

- 小红书第一条指定笔记的独立诊断最终返回成功、0条评论、has_more=false；不能把它的空评论结果解释为没有登录。
- 第二条用户链接自查修复后续采到80条评论；79条有效文本，1条被默认噪声规则过滤。该任务保留真实ID、回复关系和原作品链接。
- 正常页面加载期间可能发生客户端二次跳转；已添加恢复处理并改为等待页面提交和评论返回。采集标签页与登录页分离；不拦截或修改平台请求。

- 小红书关键词搜索已获得2个作品13条评论，分页均结束；只覆盖实际展开的回复。另存为独立任务，不与用户指定笔记混合。
